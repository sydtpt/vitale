> **Nuance crítica:** "APIs oficiais do Garmin" não é bloco único. Health API (resumos diários em JSON), Activity API (arquivos .FIT/.GPX/.TCX) e Training API (só escrita) têm coberturas radicalmente diferentes.

## Achados

**[C1]** Garmin Health API lista: Steps, Intensity Minutes, Sleep, Calories, Heart Rate, Stress, Pulse Ox, Body Battery, Body Composition, Respiration, Blood Pressure. JSON. Arquitetura "Ping/Pull **or** Push". Backfill mencionado sem limite numérico. **"Enhanced Beat-To-Beat Interval" (RR intervals, base do HRV) aparece como recurso premium / com licenciamento comercial.** | source: https://developer.garmin.com/gc-developer-program/health-api/ | publisher: Garmin | pub_date: doc viva | accessed: 2026-08-21 | confidence: medium | class: capability

**[C2]** Garmin Activity API entrega dados completos de atividade em .FIT/.GPX/.TCX; Ping/Pull ou Push; backfill via ferramentas de dev, sem limite especificado. | source: https://developer.garmin.com/gc-developer-program/activity-api/ | publisher: Garmin | accessed: 2026-08-21 | confidence: medium | class: mechanism

**[C3]** **Training API é exclusivamente de ESCRITA**: "allows you to publish workouts and training plans to the Garmin Connect calendar" — não lê VO₂max, training status nem training load. | source: https://developer.garmin.com/gc-developer-program/training-api/ | publisher: Garmin | accessed: 2026-08-21 | confidence: high | class: capability

**[C4] ⚠️ CONTRADIZ D2a-[3]/[4]** — Program FAQ afirma que o programa está ativo e aceitando solicitações ("we will confirm the status of your application within two business days"); "access to some metrics may require a license fee payment or minimum device order quantity for commercial use". | source: https://developer.garmin.com/gc-developer-program/program-faq/ | publisher: Garmin | accessed: 2026-08-21 | confidence: high | class: version/compatibility
_**VER `contradicao-programa-garmin.md` — resolvida pelo lead.**_

**[C5]** Strava API v3 reference: streams = Altitude, Cadence, Distance, Heartrate, LatLng, Moving, Power, SmoothGrade, SmoothVelocity, Temperature, Time. `DetailedActivity` tem `average_heartrate`/`max_heartrate`. **Nenhuma menção a VO₂max, HRV ou SpO₂ em toda a página.** | source: https://developers.strava.com/docs/reference/ | publisher: Strava | accessed: 2026-08-21 | confidence: high | class: capability-negative

**[C6]** Strava afirma (via canal de comunidade, não lido diretamente) que não calcula nem exibe VO₂max. | source: communityhub.strava.com via síntese de busca | accessed: 2026-08-21 | confidence: low-medium | class: capability-negative

O intervals.icu **não extrai com decimais** — "the data Garmin sends Intervals.icu doesn't have decimals". | source: https://forum.intervals.icu/t/garmin-vo2-max-from-fit-file/24268 | publisher: fórum intervals.icu | accessed: 2026-08-21 | confidence: medium | class: capability + mechanism

## Leads

- ⭐ **A distinção Health API vs Activity API é o achado mais acionável.** Para o gap do usuário (rota GPS + stream de FC), a resposta é **Activity API (arquivos)**, não Health API (resumos). Confirmar com connect-support@developer.garmin.com se VO₂max/HRV aparecem no JSON de metadados ou só dentro do binário FIT.
- **Origem real do dado no intervals.icu não determinada**: usa a API B2B oficial ou uma integração OAuth de conta pessoal (mais próxima do fluxo não-oficial)? Muda durabilidade e legalidade do caminho.
- **"Enhanced Beat-to-Beat Interval" é a pista mais forte para HRV oficial** — RR bruto de onde rMSSD se deriva, mas atrás de licenciamento comercial.
- Contradição entre agregadores e doc oficial em dois pontos reforça a regra: checar a primária antes de aceitar limitação relatada por blog.

## Procurei e não achei

- Limite numérico de backfill histórico para Health e Activity API.
- Campo "HRV" nomeado (`hrvSummary`, rMSSD, status "balanced/unbalanced") na doc da Health API — só "Enhanced Beat-to-Beat Interval".
- Referência campo-a-campo do intervals.icu — `api-docs.html` é Swagger renderizado via JS; WebFetch não extraiu o schema.
- Confirmação explícita de SpO₂ na doc do Strava (inferido por ausência geral).
- Granularidade exata (1Hz vs smart recording) dos streams nos arquivos do Activity API.
- Se o Activity API inclui metadados de VO₂max/treino no corpo JSON, fora do FIT anexado.
