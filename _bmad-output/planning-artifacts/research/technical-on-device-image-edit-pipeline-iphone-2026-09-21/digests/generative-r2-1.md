## Hypotheses checked
- **H1** (Imarello ≈10 s / ≈2.6 GB at 512², iPhone 17 Pro, reproduced independently): **not found / unconfirmed.** Zero independent klein-on-iPhone measurements retrieved (PERF.md itself: "No external measurements"). What exists: (a) Bonsai's 9.4 s / 1.5–2.0 GB (vendor, 17 Pro Max, 1/ternary-bit variant) — a similar-magnitude claim but a different actor and text-to-image only; (b) Draw Things' 12B/20B numbers on the same chip, which make ≈2 s/step for 4B@512² plausible by scaling (my inference). Qualifiers that matter: 9.9 s is the *experimental* route (default is 12.2 s / 3.5 GB), is T2I not edit, and there is no sustained-run thermal series at 512².
- **H2** (reference-conditioned editing preserves layout/faces better than low-strength SDEdit-style img2img): **not found — no independent evidence.** klein card is silent on it. Imarello ships both modes (strength img2img at 0.8; reference-latent "identity" with face-aware preservation) so an on-device A/B is possible in one codebase, but its docs publish no quality comparison and no iPhone edit timing. Mac cost of reference conditioning ≈ 1.6–2× per step (M2 8 GB, author numbers). The mechanism argument for H2 is plausible from architecture but is my prior, not retrieved evidence.
- **H3** (SD1.5-class + few-step LoRA is the pragmatic minimum): **not found / unresolved.** No few-step iPhone numbers retrieved; no quality evidence. Counter-consideration: a single-model klein path at 512² is ≈10–12 s (self-reported) — the same order as the old SD2.1-on-14-Pro-Max figure — so the "SD1.5 is much faster and smaller" premise is *unproven* in either direction this round.
- **T5**: settled — Apple primary says ImageCreator (on-device) stops working on iOS 27.
