## Hypotheses checked
- **H1 (Vision classifier supplies sky/landscape/food/people labels at near-zero cost, no VLM needed): PARTLY CONFIRMED.** Labels exist for sky (`sky`, `blue_sky`, `night_sky`, `daytime`, `sunset_sunrise`, `cloudy`), terrain/water (`mountain`, `hill`, `forest`, `beach`, `water`, `lake`, `river`), food (`food`, `drink`, `coffee`), people (`people`, `adult`, `child`, `baby`) and animals (`dog`, `cat`, `bird`, `horse`) in a 1,303-label built-in model (F2, F3). But there is no `landscape`, `selfie` or `portrait` label, so those classes must be composed from other labels or from face count/pixel stats. "Near-zero cost" is inferred (OS-built-in request, iOS 18+) — the docs give no latency/memory number (F1) and I found no measured figure. The label set is from an ~iOS 13 revision; whether iOS 27 uses another revision is unverified. Sufficient in principle for 4–6 presets; a VLM is not required to choose among them.
- **H2 (`@Generable` enum can never return an invalid case): PARTLY CONFIRMED / UNPROVEN AS WORDED.** Primary text says guided generation "fundamentally guarantees structural correctness using … constrained decoding" (F6) and docs say `@Generable` applies to "structure or enumeration" (F7), so an invalid case is not expected. But I did not retrieve a sentence that says so for enums, and the doc page makes no validity claim. Even so: (i) structural validity ≠ a sensible choice; (ii) the call can still throw (guardrail violation, unsupported language, context exceeded — F6) or be unavailable (F6); (iii) whether constrained decoding holds for non-system providers (MLX/Core AI) is unverified this round (round 1 claimed it is a provider capability).
- **H3 (MobileCLIP2 usable in a personal app, not a published one): PARTLY CONFIRMED; the "personal" half is NOT supported.** Published/commercial: prohibited ("does not include … use in any commercial product or service", F8). Personal: the licence grants a "personal" (licensee-specific) licence "exclusively for Research Purposes" = "non-commercial scientific research… sole intent to advance scientific knowledge". A personal photo-editing app is not obviously research; it is a grey zone needing a legal read, not a safe harbour. Same terms for FastVLM. Treat both as research-only.
