## Hypotheses checked
- **H1 — SD ~0.9 B img2img feasible on iPhone 17 Pro in < 60 s: partly confirmed (by proxy, not measured).** Core AI's SD recipe lists SD 1.5/2.1 at 0.9B with `CoreAIDiffusionPipeline` for iOS and an img2img VAE encoder (F7), but publishes no numbers. The nearest measurements are Core ML: SD2.1-base 512² 7.9 s end-to-end on an iPhone 14 Pro Max, SDXL 768² 31 s on a 15 Pro Max (F9) — a 3-generations-older chip already inside 60 s; a 17 Pro should be faster and img2img runs only strength x steps. Two independent 17-Pro-class results for a 4B model at 512² (~9.4-9.9 s, F2/F3) point the same way. Missing: any Core AI + img2img + iPhone 17 Pro measurement, and any quality evidence. Time is not the risk; quality and memory are.
- **H2 — ControlNet supported in the Core AI diffusion runtime on iOS: not found / not documented (leaning overturned).** The Core AI SD recipe README does not mention ControlNet, inpainting or LoRA (F7); the issue search shows nothing (F8, weak). ControlNet IS supported in Apple's older Core ML `ml-stable-diffusion` Swift package (F9) and in Draw Things (F10, snippet-only). A source-level check of `coreai-models` code was not done.
- **H3 — FLUX.2 klein 4B cannot run on iPhone: overturned as stated; true only for the stock Core AI bundle.** The Core AI int4 bundle peaks ~6.5 GB vs a claimed ~6.1 GB per-process limit (F1, single third-party source, limit unverified). But MLX-Swift 4-bit runs on an iPhone 17 Pro at 512² in 9.9 s with 2.6 GB peak (F2), and 1-bit/ternary Bonsai runs at 9.4 s / 1.5-2.0 GB on a 17 Pro Max (F3). 1024² is thermally marginal (F2: 37 s, stopped under serious thermal pressure). Licence is Apache-2.0 for 4B, non-commercial for 9B (F4). Caveat: both runnable paths are self-reported by small projects/vendor, iOS 26.6.1 not 27, and their img2img/edit path is slower/less proven.
- **H4 — Image Playground usable by third parties to restyle an existing photo: overturned for this pipeline.** iOS 27 deprecates the programmatic `ImageCreator`, moves generation to Private Cloud Compute (not on-device, not offline, usage-limited) and offers only a user-in-the-loop sheet where the source image is inspiration, "not a constraint" (F12). It cannot guarantee layout/face preservation nor run headless in a pipeline. It fails the brief's "fully on-device" criterion. (Whether the deprecated ImageCreator still works on iOS 27 devices is unresolved: F13.)

## Q-by-Q synthesis
- **Q1 landscape.** On iPhone with numbers: SD 1.5/2.1-class via Core ML (7.9 s @512², 14 Pro Max), SDXL (31 s @768², 15 Pro Max), FLUX.2 klein 4B via MLX (9.9 s @512², 17 Pro), Bonsai 1-bit/ternary (9.4 s @512², 17 Pro Max), SnapGen++ (1.8 s, 16 Pro Max, weights unverified). Core AI recipes exist for SD 1.5/2.1/3.5-M and flux2 but ship no iPhone numbers. Not found: SDXL-Turbo/Lightning/Hyper-SD/LCM on iPhone, SANA/SANA-Sprint on iPhone, Qwen-Image/Z-Image, mflux-on-iPhone numbers, Draw Things iPhone numbers.
- **Q2 img2img/inpaint/ControlNet.** Capability evidence only: Core AI img2img (yes), Core ML ControlNet + inpainting (yes), Draw Things inpaint checkpoints + ControlNet (snippet), Imarello strength-based edits (yes). **No evidence retrieved** on denoise-strength trade-offs, seam/edge artefacts around masks, depth/canny structure preservation at small sizes, IP-Adapter or T2I-Adapter on-device. Resolution/time scaling: 512²->1024² cost 3.8x time on klein 4B and pushes thermals (F2).
- **Q3 instruction/reference editing.** Only FLUX.2 klein 4B (in-context, 1-2 references) has evidence: 25 s / 43 s at 1024² on M4 Max (F1) and identity-preserving edits via reference latents in Imarello on iPhone (F2, slower path, no timing). FLUX Kontext appears only as a Draw Things wiki page (F10). Qwen-Image-Edit, OmniGen, Step1X-Edit, InstructPix2Pix, one-step distilled editors: not researched / no iPhone evidence.
- **Q4 Apple APIs.** See F12-F14 and H4. Photos Clean Up, generative backgrounds, Visual Intelligence as third-party APIs: **not researched** (budget) — gap.
- **Q5 non-diffusion.** Cheap models exist (AnimeGANv2 ~8.6 MB, fast NST) but no iPhone latency was retrieved; whole-image only; quality evidence not retrieved.

## Not on the list but relevant (new entities)
1. **PrismML Bonsai Image 4B** (1-bit/ternary FLUX.2 klein 4B): only candidate with peak RAM < 2 GB at 512² and Apache-2.0; edit/img2img support unknown. 2. **Imarello**: the one iPhone 17 Pro implementation of klein 4B found, includes strength-based restyle and reference-latent identity edit. 3. **FLUX.2 klein in-context/reference editing** as a technique: conditions on the source image as reference latents instead of SDEdit-style noising, so layout/identity do not depend on a low denoise strength (mechanism inferred from F1/F2 descriptions; quality unmeasured). 4. `john-rocky/CoreML-Models` zoo (+ Core AI sibling) for cheap non-diffusion stylisers. 5. Image Playground sheet + `externalProvider` style as a cloud fallback only (breaks "fully on-device").

## Leads worth chasing
- Second source for the **~6.1 GB per-process limit** on 12 GB iPhones (Apple docs: `com.apple.developer.kernel.increased-memory-limit`, `os_proc_available_memory`) — all memory verdicts lean on it (F1 only).
- Read Imarello source/issues: text-encoder unload strategy, img2img strength path timing, iOS 27 behaviour, thermal traces at 512² (sustained runs), whether the MLX path is embeddable in an Expo native module.
- Source-level check of `coreai-models` (flux2 + stable-diffusion) for mask inpainting, ControlNet, strength parameter, iPhone memory notes; issue #138 (ANE compile error at 64x64 transformer) may bear on iPhone deployment.
- Bonsai: is img2img/edit supported, what "accuracy" means, is the MLX runtime shippable on iOS; independent reproduction of 9.4 s / 1.5 GB.
- Whole-image restyle at low strength: find independent evidence on face/identity drift, text distortion (BFL lists distorted text as a known failure, F4), and layout retention for SD1.5-class vs klein-class; try Draw Things community threads.
- Apple APIs not covered: Photos Clean Up, generative backgrounds, Visual Intelligence, and whether deprecated `ImageCreator` still runs (on-device?) on iOS 27 devices (F13 vs F12 conflict).
- SnapGen++ weights/licence; SANA-Sprint / SDXL-Turbo / Hyper-SD few-step LoRAs on iPhone with Core ML or Core AI.
- Contradiction to keep: "klein 4B does not fit an iPhone" (F1) vs "runs in 2.6 GB / 9.9 s at 512²" (F2) and "1.5-2 GB" (F3). Not averaged: they are different runtimes (Core AI bundle with resident text encoder vs MLX/1-bit). Also F13 vs F12 (deprecated vs stops working) unresolved; F2 "passed safety gates" vs "stopped under serious thermal pressure" for 1024².
