## Hypotheses checked
- **H1 — a local Expo module can depend on Core AI / coreai-models without ejecting: PARTLY / not confirmed.** For: Expo modules are native Swift code; coreai-models is BSD-3 (vendorable); Xcode 27 is the only stated toolchain hurdle; workaround articles exist [S]. Against: the SPM route in Expo is an unmerged PR (row 1), CocoaPods/XCFramework handling unchanged, CoreAIKit and the coreai-models runtime ship as SwiftPM, and device-only "dynamic framework not embedded" failures were reported [S]. No Expo/RN project wrapping Core AI was found. Cheapest honest path = vendor the Swift sources or a config plugin; whether the system `CoreAI` framework alone (no SPM) suffices for a runtime you write yourself is [B], untested.
- **H2 — on-demand download beats bundling for weights: CONFIRMED (for multi-hundred-MB+ weights), with caveats.** Bundles are per-platform and hundreds of MB to GB (rows 15–16); Apple-hosted assets give 200 GB/100 packs with TestFlight support; CoreAIKit downloads-and-caches by design. Caveats: Apple-hosted needs a paid membership; per-pack cap and dev-build (non-TestFlight) behaviour unverified; tiny assets (LUT PNGs, presets) should simply be bundled.
- **H3 — long GPU/ANE inference finishes reliably only in the foreground on iOS: PARTLY (consistent with evidence, not proven).** iOS 26: background GPU via `BGContinuedProcessingTask` reported unsupported on all iPhones tested (Feb 2026); iOS 27 and iPhone 17 Pro untested; ANE/CPU background behaviour not evidenced either way. Design as foreground-only with `isIdleTimerDisabled`, stage checkpoints and resumability; re-test `supportedResources` on the target device first (one line of code).

## Better / unlisted options
- Vendor the coreai-models Swift sources (BSD-3) into the local module instead of consuming an SPM package — inference from rows 1 and 3.
- Keep the whole pipeline inside one Swift module: JS sends `start(jobId, inputURI, presetId)`, receives stage/progress events and a result file URI, calls `cancel(jobId)`; never tensors (row 6). Event/cancel API shape is [B]: Expo Module API `AsyncFunction` + `Events` + Swift `Task` cancellation — docs not fetched.
- `BGContinuedProcessingTask` without GPU (CPU/network work + Live Activity) is a real iOS 26 API (row 11), useful for the download step, not for GPU inference.
- Apple-hosted Background Assets vs HF download+cache (CoreAIKit style): pick by whether the paid membership is acceptable.
- Weight offloading à la Draw Things is the demonstrated way to fit big models under a RAM ceiling on iPhone (row 13).
