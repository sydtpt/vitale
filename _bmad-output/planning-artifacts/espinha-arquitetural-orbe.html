O que a varredura encontrou

Nada aqui é hipótese. Cada número saiu de uma medição no repositório em 17 de agosto de 2026.

21basenames existindo nos dois apps
85%dos commits nesses módulos mudaram web e mobile juntos
139chamadas .from() escritas à mão
14tabelas consultadas pelos dois apps
0registros de decisão no repositório
3arquivos de teste que nunca rodaram

A duplicação não é acidente de nomenclatura. Em todo-logic, são 272 linhas contra 274, com seis divergentes — uma cópia que deriva por acúmulo. E o próprio código confessa: mobile/src/lib/planned-match.ts abre com um aviso pedindo que as duas versões sejam mantidas em sincronia à mão.

As duas cópias divergem sempre nas bordas. Em moving-time, o cálculo é idêntico e a diferença é um adaptador de entrada do HealthKit. Em planned-match, o cálculo é idêntico e a diferença é a montagem da grade da semana. O núcleo nunca diverge — divergem a entrada e a apresentação. É essa observação que define a fronteira.

Fora do runtime, o conhecimento mais caro do projeto — zonas de FC como percentual da FC máxima, o dedupe multi-fonte do HealthKit, o timeout de oito segundos ao ler rotas — vive em 24 arquivos de memória fora do repositório. Esse é o acoplamento real a uma ferramenta, muito mais que o nome de qualquer pasta.

Núcleo compartilhado com adaptadores de plataforma

packages/shared é o núcleo: domínio, cálculo, vocabulário e contrato de dados, sem nenhuma API de plataforma. Os apps são adaptadores. O banco é persistência e fronteira externa.

Proibido: o núcleo importar dos apps; os apps importarem um do outro; o núcleo construir um client Supabase.

As treze invariantes

Cada uma existe porque duas unidades construídas de forma independente poderiam escolher de forma incompatível — e, na maioria dos casos aqui, já escolheram.

AD-1

Fronteira mecânica entre núcleo e adaptador

Núcleo
Impede
Duplicação por deriva — cinco pares de lógica idêntica divergindo hoje.
Regra
Módulo que não importa API de plataforma pertence a packages/shared. O critério é o conjunto de imports, nunca um julgamento sobre o que "é domínio".
AD-2

Arquivo que mistura é partido

Núcleo
Impede
Derrotar a AD-1 por co-locação: um store importa signal(), fica no app e leva a query pura junto.
Regra
Arquivo misto é dividido antes de aplicar a AD-1; a metade pura sobe. A AD-1 vale para o módulo resultante, não para o arquivo original.
AD-3

Dono único do vocabulário de domínio

Núcleo
Impede
Dois donos da mesma entidade — GPS_ACTIVITY_IDS definido em web e mobile enquanto o núcleo detém só os rótulos.
Regra
Cada conceito tem exatamente um módulo dono no núcleo. Antes de criar um módulo, o conceito é procurado: um segundo nome para a mesma coisa viola tanto quanto uma cópia.
AD-4

Contrato de schema no núcleo, client injetado

Banco
Impede
Schema escrito à mão em dois apps, com filtros que já divergem em todo_templates.
Regra
Query vive em shared/src/data/ e recebe o client por parâmetro. Cada tabela tem um módulo dono, que devolve modelo de domínio — nunca linha crua.
AD-5

Banco como exceção nomeada

Banco
Impede
Empurrar lógica ao banco por preferência, pagando atrito de migration manual sem ganho medido.
Regra
Só quando o ganho for reduzir payload ou colapsar round-trip; o precedente é activity_routes.route_overview. View exige security_invoker = true. RPC não se aplica onde o cliente precise escolher colunas.
AD-6

Edge function só para integração com segredo

Banco
Impede
Regra de negócio migrando para um runtime sem teste local nem CI.
Regra
Edge function existe para integração externa que exija segredo server-side. Lógica de negócio fica no núcleo.
AD-7

Guarda mecânica no teste

Núcleo
Impede
AD-1 a AD-4 virarem prosa não verificada — não há CI nem git hooks neste repositório.
Regra
O teste falha quando um basename duplica entre os apps fora da allowlist de stores, ou quando um módulo sem import de plataforma existe fora do núcleo. Só vale depois que o núcleo tiver runner real.
AD-8

Instância Supabase única

AdotadoBanco
Impede
Supor um isolamento de ambiente que não existe.
Regra
Uma instância serve todos os ambientes; todo trabalho de desenvolvimento escreve em dado real. Migration só com confirmação explícita; DDL destrutivo nunca sem aval.
AD-9

Build do web não injeta segredo

Adaptador
Impede
Etapa de substituição de placeholder que já existe morta no repositório e engana quem a encontra.
Regra
A anon key é pública e protegida por RLS; fica versionada em um único environment. O build de produção não substitui arquivo nem injeta segredo.
AD-10

Conhecimento estratificado por volatilidade

Conhecimento
Impede
Documentação apodrecendo por misturar o durável com o descartável.
Regra
O derivável do código não se escreve. Regra operacional verificada vai no bloco do AGENTS.md. Durável vai em docs/. Efêmero vai em _bmad-output/.
AD-11

ADR é imutável

Conhecimento
Impede
Registro de decisão virando documento vivo, que envelhece como todo documento vivo.
Regra
ADR é numerada e append-only. Mudar de ideia não edita a ADR: escreve outra que a supersede, citando a anterior.
AD-12

Estado é do app; query, cálculo e vocabulário não são

Adaptador
Impede
A máquina de estado servir de esconderijo para lógica compartilhável.
Regra
Cada app é dono da sua máquina de estado — signals no web, Zustand no mobile. Não é dono de query, cálculo nem vocabulário.
AD-13

Target de teste não pode ser stub

Núcleo
Impede
Suíte verde que não executa nada — o núcleo tem três arquivos de teste e um script echo, e eles nunca rodaram.
Regra
Workspace cujo npm test não executa um runner de verdade não declara target test. Falhar é aceitável; mentir que passou, não.
